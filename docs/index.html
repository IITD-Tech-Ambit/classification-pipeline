1 · Status

Recommended shipping file: outputs/classification_v2_2_candidate.jsonl, accepted after v2.2’s targeted Sonnet correction and model-judged validation (outputs/v22_run_report.md, decision ACCEPT_v2_2 in outputs/work/v22_decision.json).

  • v2.2 local ingest reported 9 themes / 80 domains, classified 67,802 / unclassifiable 2,496 (outputs/v22_ingest_report.md).
  • v3 blanket re-classification was experimented with and not recommended for ingest as-is (outputs/REFINEMENT_REPORT.md).
  • Production cutover of these labels is a separate team decision; this repo records local testing ingest only.

2 · Taxonomy

Final system is two-level:

  1. Thematic area — 9 fixed, human thematic areas with written scope / tie-break notes.
  2. Domain — induced under each theme (clustering + LLM naming/consolidation, later audit-driven gap fills).

There is no subdomain level and no controlled topic vocabulary in the accepted classifier output. Each paper gets one thematic_area + one domain (or unclassifiable).

Canonical taxonomy files for the accepted run: outputs/taxonomy-draft-v22.json / taxonomy-draft-v22.md.

3.1 Hygiene

Rule gate before API spend (outputs/hygiene_summary.md): junk patterns (editorial, erratum, preface, …) and insufficient text → unclassifiable; remaining papers proceed to classify (some flagged title-only).

3.2 Taxonomy discovery (embeddings used here)

  • Sample / pool papers per theme; embed with BAAI/bge-base-en-v1.5 (pipeline/s02_embed.py).
  • Optional Colab path for bge-large embeddings (colab/embed_bge_large.ipynb).
  • Cluster (e.g. KMeans silhouette sweep in pipeline/s03_cluster.py and later v2 scripts); LLM names and consolidates domains.
  • Theme-correction / pool rebuild steps refine domain lists before the overnight classify run.
Important: final classification prompts contain the full theme→domain taxonomy. There was no production “embed → top-k path shortlist → LLM” funnel for the accepted labels.

3.3 Full-corpus classify (overnight v2)

From outputs/OVERNIGHT_REPORT.md:

  • 70,298 corpus papers accounted for in classification_v2_final.jsonl.
  • Haiku classified eligible papers with prompt-cached full taxonomy; Sonnet re-did low-confidence / schema-fail rows.
  • Shared library: pipeline/s15_classify_lib.py (+ s15_run_haiku.py, s16_run_sonnet.py, s16_finalize.py).
  • API spend for that overnight pass is reported in the overnight report (Haiku + Sonnet totals there).

3.4 Targeted correction → v2.2

  • v2.1: budget-capped Sonnet queue on low-conf / confusion rows → classification_v2_1_candidate.jsonl.
  • v2.2: closed taxonomy gaps; Sonnet re-scored a high-yield queue; conservative acceptance gate; Opus pairwise validation favored v2.2 → accepted file above.

5 · Validation (honest)

No human gold-standard accuracy is claimed. The team has LLM-proxy audits and random-subset model adjudications. A human-labeled gold template exists (outputs/goldset_template.csv) so disagreements can be adjudicated later — that human pass is not documented as completed in this repo’s reports.
  • outputs/goldset_accuracy_report.md — independent Sonnet re-label vs pipeline labels on a stratified sample; reports theme/domain agreement (proxy), with explicit caveats in that file.
  • outputs/v21_validation_random_subset.md / v22_validation_random_subset.md — model judge (Opus) pairwise comparisons used as acceptance gates for targeted patches.
  • outputs/audit_50_random*.md — smaller audit writeups.

When quoting quality numbers, say “LLM-proxy agreement” or “model-judged win margin”, not “human-verified accuracy.”

7 · Local ingest vs production

Scripts under pipeline/i*.py and v22_ingest_local.py support writing labels into a local research_ambit Mongo and rebuilding atlas/KG inputs for app testing. Reports such as v22_ingest_report.md document that local path.

This documentation does not claim production deployment. Production rollout remains an explicit team decision outside this pipeline repo’s acceptance criteria.

8 · Historical proposed plan (not executed)

Early design work sketched a quality-first self-hosted stack: two RTX 3050-class laptops, local MoE/dense voters, embedding-centroid candidate pruning, domain→subdomain→topic induction, multi-voter agreement before write-back, and a hard human gold accuracy bar before full-corpus runs — with a “no external LLM APIs” constraint.

What diverged in practice:

  • Final labels used Anthropic Claude APIs (Haiku / Sonnet / Opus-as-judge), not the self-hosted voter funnel.
  • Taxonomy stopped at theme → domain; subdomains/topics were not shipped.
  • Classify-time path used the full taxonomy in prompt, not embedding shortlists.
  • Acceptance used model-judged audits, not a completed human gold set meeting a ≥95%/≥85% bar.

Keep that design as historical context only; do not treat it as the production architecture.
